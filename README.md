# АТехника — Telegram-бот коммерческих предложений

MVP: текст/голос → проверенный каталог → черновик → правки и версии → завершение → DOCX/PDF.
Python 3.12, aiogram 3, PostgreSQL, OpenAI API, docxtpl, LibreOffice, закрытое S3-совместимое хранилище.

## Что реализовано

- Личные сообщения, меню команд и кнопки, текстовый и голосовой ввод.
- Распознавание голоса с обязательным подтверждением расшифровки до обработки.
- Structured Outputs для извлечения полей. Нет исполнения SQL/команд или прав доступа, предложенных моделью.
- При отсутствии AI работает ручной формат полей, описанный ниже.
- Каталог с SKU, комплектациями, валютой, сроком актуальности и импортом CSV начальником.
- Подбор техники по точному SKU или однозначному названию. Неоднозначный выбор требует уточнения.
- Цену за единицу в рублях с НДС задаёт менеджер. Если цена пропущена, бот запрашивает её для каждой позиции до создания КП.
- НДС включён в цену; по умолчанию 22%. Каталог может содержать явную другую ставку.
- Сумма по количеству и выделение включённого НДС — Decimal. Цена каталога и курс валют в новых КП не используются.
- Роли, отделы, отключение доступа. Менеджер может самостоятельно завершить своё КП.
- Новая редакция всегда создаёт новый черновик. Старые версии и файлы сохраняются.
- Очередь генерации в PostgreSQL с восстановлением просроченной блокировки и ограниченными повторами.
- Неизменяемые версии бланка в закрытом хранилище. Word и PDF выдаются только после проверки прав.
- Журнал действий, защита от повторной доставки сообщения и конфликта редактирования.

## Права

| Действие | manager | sales_head | chief |
|---|---|---|---|
| Создание КП | Да | Да | Да |
| Просмотр, правки, завершение, файлы | Свои КП | КП своего отдела и свои | Все КП |
| Изменение включённой ставки НДС | Нет | Нет | Да, с причиной, в новой версии |
| Импорт каталога | Нет | Нет | Да |
| Загрузка общего фирменного бланка | Да | Да | Да |
| Указание цены в своих КП | Да | Да | Да |
| Пользователи и роли | Нет | Нет | Да |
| Скидки отдельным полем, изменение предоплаты | Нет | Нет | Нет |

`/vat` сохраняет итоговую цену с НДС, меняет выделенные НДС и сумму без НДС.
Это правило MVP: иной налоговый расчёт (например «без НДС», а не ставка 0%) потребует отдельного расширения.
Доступ руководителя определяется отделом, зафиксированным при создании КП.

## Быстрый локальный запуск

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
cp .env.example .env
mkdir -p private
```

Заполните `.env`. Для локальной работы допустимы:

```dotenv
APP_ENV=development
DATABASE_URL=sqlite:///private/dev.db
STORAGE_BACKEND=local
LOCAL_STORAGE_PATH=private/objects
```

Установите LibreOffice Writer и ffmpeg. Затем:

```bash
# Alembic читает DATABASE_URL из окружения, а не .env
export DATABASE_URL=sqlite:///private/dev.db
alembic upgrade head
python -m bp_bot
```

В production SQLite и local storage запрещены проверкой настроек. Нужны PostgreSQL и S3.

## Настройка на Railway

Приложение подготовлено для контейнерной сборки. Изменения в ветке разработки не предназначены для деплоя.
После проверки PR и заполнения секретов можно слить его в подключённую ветку `master`.
`railway.json` задаёт Dockerfile, миграцию `alembic upgrade head` перед запуском и `python -m bp_bot`.

1. Создать PostgreSQL в проекте и передать `DATABASE_URL` в сервис бота. URL `postgresql://` нормализуется автоматически.
2. Создать закрытый S3 bucket и передать `S3_BUCKET`, `S3_ENDPOINT_URL`, `AWS_ACCESS_KEY_ID`,
   `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION` (например `auto`, если требуется провайдером).
3. Задать `BOT_TOKEN`, `BOOTSTRAP_ADMIN_ID` (числовой Telegram ID), `BOOTSTRAP_ADMIN_NAME`.
4. Для AI задать `OPENAI_API_KEY`, `OPENAI_TEXT_MODEL` (модель с Structured Outputs),
   `OPENAI_TRANSCRIBE_MODEL` (модель для файловой транскрипции). Имена моделей не зашиты в код.
5. `APP_ENV=production`, `STORAGE_BACKEND=s3`. Ровно **одна реплика**, без режима сна.
   PostgreSQL advisory lock дополнительно исключает два активных экземпляра polling.
6. Проверить, что у Telegram-бота нет установленного webhook. Приложение не удаляет его автоматически.
7. Слить проверенный PR в подключённую ветку. Убедиться, что миграции и запуск завершились успешно.
8. Начальник отправляет `/start`, загружает бланк и каталог, затем добавляет менеджеров.
9. Выполнить реальный сценарий создания и правки КП, проверить Word/PDF и перезапуск сервиса.

Публичный HTTP-домен для polling не нужен. Проверяйте работоспособность через `/start` и журналы сервиса.
Для обновления приложения нужен короткий перезапуск: одновременно работающие копии с одним токеном запрещены.

## Бланк и каталог

Исходный прайс, фирменный DOCX и документы клиентов **не хранятся в публичном Git**.

Любой активный сотрудник может загрузить чистый фирменный DOCX с подписью `/letterhead`.
Общий сохранённый бланк подставляется автоматически; согласование руководством не требуется.
Приложение сохраняет шапку и подвал, формирует содержимое КП самостоятельно. Макросы,
вложенные объекты, внешние ссылки и пользовательские Jinja-команды запрещены.
Макет ориентирован на согласованный бланк АТехники A4 с верхней шапкой и нижними логотипами.
После изменения бланка старые версии продолжают использовать прежний файл.

Для каталога отправьте UTF-8 CSV с подписью `/import`. Образец колонок: `docs/catalog.example.csv`.
Это демонстрационная строка, не товар компании. Не импортируйте её в рабочий каталог.

| Колонка | Значение |
|---|---|
| sku | Уникальный код; латиница, цифры, `_`, `-` |
| name / configuration | Название и фактическая комплектация |
| price | Необязательная справочная цена; в новые КП не подставляется |
| currency | RUB, EUR, USD, CNY |
| supply | stock — склад; paid — оплачено; order — под заказ; unknown — не уточнено |
| price_date / valid_until | Необязательные даты справочного прайса, ISO YYYY-MM-DD |
| vat_rate | Включённая ставка НДС (22 по умолчанию при отсутствии колонки) |
| active | true / false |

Импорт обновляет перечисленные SKU; отсутствующие строки не удаляются. Для снятия позиции используйте `active=false`.
stock/paid допускают только RUB. При отсутствии цены оставьте поле пустым; нулевая цена не принимается.
Названия, комплектации и характеристики должны соответствовать источнику. Даты и наличие не угадываются.

Новые КП используют структуру образца: описание, преимущества и фото при наличии данных,
таблица характеристик, цена менеджера и коммерческие условия. Профили моделей сохраняются
в `app_values` (`product_profile:<SKU>`), фото — в закрытом хранилище. Исторические версии
сохраняют прежний шаблон; данные профиля фиксируются при выборе позиции.

## Использование

Начальник добавляет сотрудника:

```text
/user 123456789 manager main Иван Петров
/user 987654321 sales_head main Руководитель продаж
```

Неизвестному пользователю `/start` показывает его ID, но не даёт доступ к каталогу или КП.
`BOOTSTRAP_ADMIN_ID` применяется только при пустой базе и не восстанавливает отозванные права на перезапуске.
Для первого менеджера можно задать `BOOTSTRAP_MANAGER_ID` и `BOOTSTRAP_MANAGER_NAME`.
Он создаётся вместе с начальником только при первоначальной настройке пустой базы, в отделе `main`.
ID начальника и менеджера должны отличаться. После первого запуска пользователями управляет начальник через `/user`.

Текстовый запрос с настроенным AI:

```text
Сделай КП для ООО Заря: GRITAN БНП 401 с тентом, 1 штука, цена 8 350 000 рублей с НДС.
Поставка в течение 10 рабочих дней после оплаты, предложение до 5 ноября 2026.
```

Без AI:

```text
/new клиент=ООО Заря; позиции=BNP401:1:8350000; поставка=10 рабочих дней после оплаты; до=2026-11-05
```

Бот покажет карточку. Если обязательных данных не хватает, они будут перечислены.
Для уточнения нажмите «Изменить» или используйте:

```text
/edit 1 1 клиент=ООО Новый клиент; до=2026-11-10
```

Получится версия 2; версия 1 сохранится. При замене товаров перечислите **весь** состав:
`позиции=SKU1:1:100000,SKU2:2:200000`. Свободный текст количества без названия товара не считается безопасной заменой состава.
Срок поставки задаётся числом рабочих или календарных дней (1–730) после полной оплаты;
если тип дней не указан, используются календарные. Произвольные условия в это поле не допускаются.
Простая правка клиента/сроков сохраняет цену. При повторном выборе позиций нужно указать цены заново.
Для КП с одной позицией можно изменить только цену: `/edit 1 1 цена=2730000`.
Без цены каждой позиции завершение и подготовка файлов запрещены, в том числе для старого черновика.

После проверки нажмите «Завершить», затем «Word и PDF». Первая кнопка файлов ставит генерацию в очередь;
через несколько секунд повторное нажатие выдаёт документы. Очередь переживает рестарт. При трёх неудачах
новое нажатие запускает повторную попытку. Отдельных автоматических рассылок клиентам нет.

Начальник меняет включённую ставку НДС:

```text
/vat 1 2 10 Причина изменения ставки
```

Получится версия 3 в статусе «Черновик», требующая нового завершения.

## Надёжность и ограничения MVP

- Групповые чаты не обслуживаются: работа только в личных сообщениях.
- Голос: до 3 минут / 10 МБ. Файлы ffmpeg/LibreOffice временные и удаляются после обработки.
- Пароли и API-ключи — только переменные окружения. В логах ошибок не печатаются запросы,
  реквизиты, токены, тела API-ответов и полные исключения внешних сервисов.
- Каталог — до 2000 строк за импорт; запрос — до 20 позиций; выдача каталога/списка КП — до 30 результатов.
- Во время обработки одного AI-запроса новые сообщения ждут в очереди Telegram; генерация документов
  работает независимо. Масштабирование на несколько polling-процессов в MVP не поддерживается.
- Не реализованы CRM, скидки, рассрочка, автоматическая отправка клиенту, импорт правок из Word,
  складское резервирование и автоматическое обновление каталога из PDF.
- Гарантия и сервисные обязательства не выдумываются: добавляются в шаблон после предоставления
  утверждённого текста. Базовые постоянные условия — предоплата и самовывоз.
- Для production настройте резервные копии PostgreSQL и versioning/retention хранилища средствами
  провайдера. Проверьте восстановление в отдельной тестовой среде. Код не создаёт эти ресурсы автоматически.
- Данные клиентов и расшифровки запросов передаются провайдеру AI, если он включён.
  Цена извлекается только из явного указания менеджера; права доступа не определяются моделью.

## Проверки

```bash
ruff check .
python -m pytest -q
```

Локально тесты используют временную SQLite. Для PostgreSQL задайте `TEST_DATABASE_URL`
**только отдельной тестовой базы**: тесты удаляют и создают таблицы.
CI использует изолированную PostgreSQL 16, проверяет миграцию и тесты. Живые Telegram/OpenAI/S3
не вызываются тестами. Для smoke-проверки документа нужен LibreOffice; пример запуска в `docs/validation.md`.
