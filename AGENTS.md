# Business Proposial / АТехника

## Начало работы: граф проекта

Перед анализом архитектуры, поиском причины ошибки или изменением кода:

1. Проверь `graphify-out/graph.json` и `graphify-out/BUILD_INFO.json`.
2. Сверь хеши файлов из BUILD_INFO с исходниками. Граф относится к указанной ветке и охватывает только перечисленные файлы. При расхождении обнови граф по текущим исходникам, сохранив семантические связи документации. Не используй устаревший граф как подтверждение фактов.
3. Начни исследование задачи с `graphify query "<задача и ключевые имена модулей>" --graph graphify-out/graph.json`. Для конкретного узла используй `graphify explain "<имя>" --graph graphify-out/graph.json`, для связи — `graphify path "<A>" "<B>" --graph graphify-out/graph.json`.
4. Прочитай актуальный код найденных модулей перед выводами и правками. Граф помогает ориентироваться; исходники и проверки остаются источником истины. Метки INFERRED/AMBIGUOUS и ограничения из diagnostics.json не являются доказанными связями исполнения.
5. Если Graphify отсутствует, используй изолированную установку `uv tool install graphifyy` (официальный пакет с двумя y). Не устанавливай хуки, не меняй глобальные инструкции и не запрашивай API-ключи только ради структурного анализа кода.
6. Если граф или инструмент недоступен, сообщи об этом кратко и продолжи анализ исходников. Не блокируй задачу и не создавай видимость выполненного Graphify-запроса.

После изменений структуры кода обнови граф, отчёт и BUILD_INFO.json. Сохраняй исходные связи и замечания диагностики. Не включай секреты, персональные данные, каталоги товаров, фотографии, виртуальные окружения и временные импортеры в граф архитектуры.
